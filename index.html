    📥 Import School Data

    ADMIN & PRINCIPAL

    Bring an existing school register into Little Feet without manually recreating each learner. Upload an Excel or CSV export from the school system, review the detected rows, then confirm the import. Duplicate learner records are skipped and reported.

    1. Upload a register

    Supported formats: .xlsx, .xls, and .csv. Use column headings such as Learner Name, Grade/Class, Parent Name, Parent Email, Medical Notes, Emergency Contact, and Authorised Pickups.

    Paper records and scans

    For privacy, this portal does not send child records from a photo or PDF to a public AI service. Scan paper files into a spreadsheet using your school-approved OCR or scanner, then upload the reviewed Excel/CSV export here.

    Every imported learner must be reviewed before submission. Medical, emergency-contact, and pickup details are encrypted when saved.

    Duplicate protection

    Records are matched by learner name, class/grade, and parent email. A duplicate does not overwrite the existing learner record; it is listed for review after the import.

    SA-SAMS & DBE/LURITS Integration

    Three integration routes are tracked separately so schools can see what works now, what is waiting on DBE, and what can use the established SA-SAMS submission chain.

    3 INTEGRATION ROUTES

    1. Little Feet SA-SAMS spreadsheet bridge

    AVAILABLE NOW

    Import a learner/parent spreadsheet exported from SA-SAMS into this school's real Little Feet learner register. Little Feet maps common learner name, surname, grade, register class and guardian contact columns, previews the result, then sends approved rows through the same bounded, tenant-isolated production import used by the learner register.

    Use this when: a school already has learner data in SA-SAMS/Excel/CSV and wants it brought into Little Feet safely.

    2. Direct Little Feet → DBE/LURITS (LASS)

    PENDING DBE / LASS APPROVAL

    DBE documentation recognises third-party school systems through the LURITS Accredited Software System (LASS) pathway. Direct Little Feet → DBE/LURITS submission remains disabled until the current official third-party interface package and LASS conformance requirements are obtained, implemented and validated.

    Use this when available: Little Feet submits through the official approved third-party LURITS interface without pretending an unofficial XML format is valid.

    3. Little Feet → SA-SAMS → LURITS submission chain

    VERIFIED EXTERNAL PATHWAY · ADAPTER NEXT

    Established South African school platforms use a second practical route: generate a SA-SAMS-compatible database/export, validate it in SA-SAMS, complete Module 17 LURITS Approval, then continue through the applicable Valistractor / DDD / district or provincial submission process to LURITS.

    Little Feet status: this pathway is documented, but the Little Feet SA-SAMS database export adapter is not enabled until its target database structure/version has been verified. No fake SA-SAMS database file will be generated.

    Submission chain: Little Feet export → SA-SAMS validation → Module 17 → Valistractor / DDD / district or provincial channel → LURITS → feedback back to the school system.

    LURITS feedback handling

    SHARED BY ROUTES 2 & 3

    Documented LURITS feedback is returned as XML files, commonly packaged in ZIP archives. The integration design tracks TransactionCategoryID, returned learner/educator LURITS numbers, validation results and submission errors so feedback can be matched back to the correct school records.

    Documented LURITS transaction lifecycle being tracked

    Tx04 learner registration · Tx05 transfer-in · Tx07 learner biographical maintenance · Tx09 transfer-out/leaving · Tx12 promotion/progression · Tx13 educator registration · Tx14 educator maintenance · Tx16 educator leaving.

    Official DBE package still required

    BLOCKED EXTERNALLY

    The remaining direct-submission work is intentionally blocked until DBE supplies or confirms the current authoritative material:

    • Current LURITS 3rd Party Software Amendment Specification.
    • Current interface/XSD schema and DBE code tables or enumerations.
    • Accepted XML examples and the current feedback schema.
    • Current transaction sequencing, file naming and submission transport requirements.
    • Current LASS vendor registration, accreditation, testing and conformance process.

    Implementation rule: no guessed, reverse-engineered or unofficial XML schema will be used for production LURITS submissions.
